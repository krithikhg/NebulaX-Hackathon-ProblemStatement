Which model won, and how we know

Every score is out-of-sample. Door uses a chronological split because the segments come from one continuous stream; Rail reports nested CV because the class priors are themselves tuned; SHM uses leave-one-out on 64 files. Two rail approaches that theory favoured — wavelength normalisation and per-axle-box modelling — were tested and rejected on the evidence.

What this is. One app across four rail-vehicle subsystems: saloon doors, air conditioning, rail corrugation and structural fatigue.

Design principles

  • Localise, don't just detect. Every output names the asset — which cycle, which car, which rail side, which measurement point.
  • The fleet is the baseline. Where siblings exist (cars on a train, rails on a bogie), they are compared against each other so ambient conditions cancel out.
  • Physics before black boxes. Door resistance shows up in motor current; fatigue damage follows Miner's rule. Fitting known physics beats deep models on datasets this small, and is far easier to defend to an engineer.
  • Schema-agnostic loading. Column sets differ between files and fleets, so parsers read each file's own headers.

Where it runs. Everything runs in your browser. The trained models ship as static JSON and are evaluated client-side, so telemetry files are never uploaded — a 17 MB rail recording is analysed locally in about a second.
